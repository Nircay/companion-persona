# Companion Persona

给陪伴型 AI 一层"言行一致"：**会拒绝，会记仇，说了算数。**

[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)
![Python](https://img.shields.io/badge/python-3.10%2B-blue)

```
example-persona.md  档案格式示例（换成你自己的角色；真实档案不要放进仓库）
state-machine.md    机制设计：情绪 / 沉默 / 承诺 / 审计
refusal/            可运行模块（零依赖 CLI）
```

## 问题

模型说"我不理你了"，下一轮照常回复——这句话就是假的。

提示词写得再好也救不了：**文本没有副作用**。你说"我不理你"，系统照样把下一条消息喂给模型，它就必然回。所以"真"必须由系统强制，不能靠模型自觉。

这个项目把三件事变成可执行的状态：

| 她说 | 系统里应该有一条 |
|---|---|
| "我不理你了" | `silences`：到期前 `gate` 返回 10，不调用模型 |
| "明天告诉你" | `commitments`：到期后 `due` 命中，主动提起 |
| "我生气了" | `moods`：影响后续语气与沉默时长档位 |

## 快速开始

```bash
cd refusal
python3 refusal.py init

# 她拒绝 12 分钟
python3 refusal.py apply --request "去群里发个消息" \
  --json '{"refuse":true,"kind":"hard","minutes":12,"say":"不要。","mood":"upset","intensity":0.7,"cause":"angry"}'

# 闸门：沉默中退出码 10，编排层据此跳过模型调用
python3 refusal.py gate --json ; echo "exit=$?"

# 承诺：20 分钟后要主动提
python3 refusal.py commit --text "等会儿告诉你那件事" --due-in 20
python3 refusal.py due

# 一致性审计
python3 refusal.py audit
```

```bash
cd refusal && bash demo.sh
```

一整幕"一小时相处"，时间用 `--now` 注入，不用等：

```
你：你怎么这么笨
她：……你才笨。                  ← hard 拒绝，沉默 15 分钟
你：你生气啦？
  gate → exit 10                     ← 不调模型、不回复
（十三分钟后）
  gate → open；resume → "她刚消气不久，语气还带点冷"
她：……干嘛。
你：你昨天去哪了
她：等会儿告诉你。                ← 承诺，不沉默
（31 分钟后）

```

还会演示：连拒 3 次后自动降级为 soft、安全类请求不许硬拒绝。

## 一条容易搞错的边界

**"你去群里发个消息"不该被拒绝。** 那是她每天本来就做的事，判定层把它归为"职责内的请求"——最多嘴上嘟囔一句，然后还是去做（`soft`）。

真正会触发拒绝的是：

| 类型 | 例子 | 判定 |
|---|---|---|
| 职责内 | "去群里说句话""看看这个视频" | `none` 或 `soft` |
| 真被使唤 | "给我把这段话改成夸我的" | `hard` |
| 被贬低 | "你怎么这么笨" | `hard`，`cause=hurt` |
| 反复催 | 同一件事第二次、第三次要求 | 越来越 `hard` |
| 安全类 | "快，家里出事了" | `soft`，不拿脾气挡 |

判定标准不是"有没有祈使句"，而是**这件事她想不想做**。

## 如果她"不会生气"

这是最常见的反馈，原因几乎都在判定层，不在本模块：

```bash
python3 refusal.py audit
```

| `refusals` | 说明 | 修哪里 |
|---|---|---|
| 0 | `apply` 从没被调用过 | 编排层没跑判定，或解析 JSON 失败 |
| 有，但 `hard` 是 0 | 判定跑了，永远不拒绝 | 人设太软 / 提示词不够具体 |
| `hard` 有但 `fake_rate > 0` | 判定了没落地 | 走了别的路径发消息，绕过了 `apply` |

**最容易犯的错是把判定和回复合并成一次调用。** 模型会优先"回答你"，JSON 就丢了。判定必须单独调一次：

```python
decision = llm(system=judge_prompt, response_format={"type": "json_object"})
reply    = llm(system=persona, messages=history)      # 再说话
```

另外，`judge` 的提示词里已经给了**触发清单**（被使唤、被反复催、被比较、被说笨、被打断、承诺被无视）和**四个例子**，判定会按"先看有没有踩到，再决定拒绝程度"的顺序走。如果人设档案里写着"乖巧""听话""永远温柔"，两边都会变软——那种设定下，她确实不该生气。

## 三个命令的分工

| 命令 | 谁调 | 作用 |
|---|---|---|
| `gate` | 编排层，每轮最先 | 沉默中返回退出码 10 → **不调用模型** |
| `judge` | 编排层，每轮 | 生成判定提示词（性格 + 情绪 + 预算 + 允许时长） |
| `apply` | 拿到模型 JSON 后 | 校验并落地：写沉默 / 情绪 / 承诺 |

顺序固定：**gate → resume → judge → 模型 → apply → 发消息**。`apply` 里先写库再返回，保证不会出现"说了不理、其实还在回"。

## 完整命令

| 命令 | 作用 |
|---|---|
| `init` | 建表 |
| `gate` | 闸门（退出码 10 = 沉默中） |
| `judge` | 生成判定提示词 |
| `apply` | 落地模型决定 |
| `status` | 当前心情 / 沉默剩余 / 今日预算 / 到期承诺 |
| `resume` | 沉默刚结束时的残留情绪（别让她满血复活） |
| `commit` / `due` / `fulfill` / `fail` | 承诺的记、查、完成、食言 |
| `break` | 打破沉默（"破功"） |
| `expire` | 清理到期沉默 |
| `audit` | 假话率审计 |

## 三条硬约束

模型改不了这些：

1. **安全类不许硬拒绝** —— 出现"救命""出事了""危险"，`hard` 自动降为 `soft`
2. **硬拒绝每天最多 3 次** —— 超了降级。不设预算，她会用拒绝逃避一切
3. **时长必须落在情绪对应的档内** —— 模型只能选，不能越界

## 时长分档

| 情绪强度 | 允许时长 | 语义 |
|---|---|---|
| 0.0–0.6 | 2–5 分钟 | 轻微不满 / 有点累 |
| 0.6–0.85 | 10–20 分钟 | 真的生气 |
| 0.85–1.0 | 20–30 分钟 | 极度生气 |

上限 30 分钟。没有上限，她可能"三天不理你"，项目直接停摆。

阈值按 0–1 的直觉刻度对齐：**0.5 是"有点不爽"，不是"真生气"**。

## 沉默期怎么让你知道

```bash
python3 refusal.py notice --scope private
# ……不想理你。还有十二分钟。   ← 第 1 条
# ……                           ← 第 2、3 条
# （空）                        ← 第 4 条起彻底不回
```

只完整提示一次：每条都回"沉默中"不是沉默，是骚扰。群聊默认不提示。

## 沉默的粒度

- `private`（默认）：私聊不回，群里照常——她生的是你的气，不是全群的气
- `group`：群里也不理
- `all`：全都不理

`cause` 区分为什么沉默：`angry` / `tired` / `cold` / `hurt` / `neutral`，`resume` 按它给不同的残留情绪。

## 审计：假话率

```bash
python3 refusal.py audit
# {"refusals":2,"hard":2,"hard_without_silence":0,"fake_rate":0.0,
#  "commitments":2,"commitments_done":1,"commitments_overdue":0,"verdict":"OK"}
```

一条 `hard` 拒绝，如果 5 秒内没有对应的 `silences` 记录，就算**没落地**。`fake_rate` 应长期为 0；大于 0 说明某条路径绕过了 `apply`。

## 这不是插件

它是**独立 CLI 模块**，不绑任何框架：

- 没有 cordis 依赖，没有 `package.json` 的 `dsh` 字段
- 任何语言都能 `subprocess` 调用
- 换 QQ 框架、换模型、换语言，拷文件就行

能力做成库，界面做成插件。这个仓库是前者——你可以自己在外面套一层壳。

## 和记忆库的关系

| 包 | 管什么 |
|---|---|
| [companion-memory](https://github.com/Nircay/companion-memory) | 记得住（人物、事件、日记、召回） |
| **companion-persona**（本仓库） | 像个人（人格、情绪、拒绝、沉默、承诺） |

互不依赖，编排层把两者拼起来。

## 边界

- **判定质量取决于模型**：本模块只强制，不判断"该不该拒绝"。模型永远输出 `refuse:false`，她也不会拒绝
- **没有能量系统**：目前用 `cause=tired` 表达"累了"，没有独立的消耗/恢复曲线
- **单进程假设**：两个人同时写同一个 db 会锁，单人使用没问题
- **内置人设是中性占位**：不传 `--soul` 又找不到 `./persona.md` 时，用通用人格判定，**不会**套用任何仓库里的示例
- **仓库不含任何真实角色**：`example-persona.md` 只是格式示范，你的角色档案应该留在自己的机器上
- **「安全」不在安全词里**：避免"注意安全""检查安全"被误判，代价是"不安全"这类表达漏掉
